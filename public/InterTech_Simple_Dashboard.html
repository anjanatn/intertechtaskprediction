Model Card & Technical Validation Note

Calibrated Random Forest · Validation and scope note

1. Model Overview & Architecture

The champion delay prediction model is a Calibrated Random Forest Classifier trained on historical task records. Isotonic calibration via CalibratedClassifierCV is used to improve how closely predicted probabilities track observed delay likelihoods.

2. Validation Methodology (Chronological vs. 5-Fold CV)

To eliminate temporal data leakage (where future task features leak into past predictions), the pipeline was validated using two independent evaluation schemes:

  • 5-Fold Stratified Cross-Validation: 72.0% Accuracy, 77.8% ROC-AUC, 43.7 MCC.
  • Chronological Time-Split Validation: The oldest 80% of dated closed tasks train the model; the newest 20% are held out. Discipline-history features are calculated using the older records only. Holdout metrics are generated and stored on each training run.

3. Naive Baseline Comparison & Predictive Lift

The training pipeline compares the chosen model with an explicit naive baseline: flag every task as high risk. It also records the always-on-time baseline for context. Both baselines and chronological-holdout metrics are saved in the dashboard data at training time, so any claimed predictive lift can be inspected rather than assumed.

4. Class Imbalance Handling & Minority Class Metrics

Delayed tasks represent a minority class (~43.6%). To prevent class imbalance bias, model training incorporates class_weight='balanced' cost-sensitive reweighting. Performance metrics focused specifically on the minority delayed class (Target = 1):

5. Scope & Known Limitations

  • Simulated data: The source dataset is synthetic and has not been validated against real project outcomes.
  • Project scope: The predictive workflow is demonstrated on the baseline PRJ001-style dataset; filters for other project IDs are interface-level views, not separately validated models.
  • Pre-Execution Boundary: Model predicts delay risks prior to task execution based on initial scope and workload intensity. Unpredictable black-swan events (weather disasters, vendor bankruptcy) require real-time site updates.
  • Exploratory modules: The 3D site view is a risk visualisation only. It is not an input to the model and does not produce operational recommendations.
